Do not mark a criterion complete based only on code presence: all outcomes that require a real Supabase project remain open until an owner provisions the Auth account and allowlist, applies the migration and verifies the live RLS/Storage policies. ## Public storefront and brand presentation
- [ ] Build an elegant, feminine, culturally appropriate, refined and trustworthy premium modest-fashion storefront. Use ivory `#F6F0E7`, sand beige `#D8C4AD`, mocha brown `#594337`, muted gold `#B6975A`, dark text `#292522` and white `#FFFFFF`; use serif headings and readable sans-serif body text; keep generous spacing and prioritize clothing photography. Avoid excessive gradients, neon, unnecessary animation, invented business identity, and overly decorative motifs.
- [ ] The homepage supports an optional editable announcement and hides it when disabled or empty. It does not invent discounts or delivery promises. The header has a replaceable brand name/logo, Home, Shop, Collections, About and Contact links, WhatsApp action, responsive mobile menu, keyboard navigation and visible focus states.
- [ ] The hero displays “Elegance in Every Layer.” and “Discover thoughtfully designed modest wear that brings together comfort, confidence, and timeless style.” with “Explore the Collection” and “Order on WhatsApp” actions, premium fashion imagery and readable mobile text.
- [ ] Show visual cards for Abayas, Hijabs, Khimars, Jilbabs, Modest Gowns and Custom-Made Outfits, each linked to its category or custom-order enquiry. Show only admin-featured published items in Featured and only admin-flagged items in New Arrivals. Each product card includes photograph, name, supplied price only, concise configured options, details link and WhatsApp action.
- [ ] Include custom-order introduction/action; editable brand story without invented biography, qualifications or history; genuine customer testimonials only when supplied and authorized (hide when none); footer category links, configured brand/contact/WhatsApp/Instagram information, and links to applicable sizing, delivery, exchange and privacy information.
- [ ] Provide About, Contact, FAQ, sizing, delivery, exchange/return and privacy pages/sections. Business-specific content must be configurable. Do not invent fees, return conditions, payment methods, locations/addresses or other policies.

## Catalogue, categories and product details
- [ ] Shop displays a responsive catalogue of published products only, with product-name search, category filtering, meaningful price sorting, loading/error/empty states and clear product-detail links. Drafts/unpublished products must not appear in storefront queries, search, category views, cached public data or rendered pages.
- [ ] Category pages display the category name, optional description and matching published products; the six initial categories remain flexible/admin-manageable; a category with no published products has a helpful empty state.
- [ ] Product details show name, image gallery, configured price (or clearly say to enquire for pricing), description, category, available sizes/colours only when configured, fabric/care only when supplied, availability, quantity when applicable and a WhatsApp order CTA. Validate selected options before generating an enquiry and disallow options the product does not offer. Do not show irrelevant selectors. If unavailable, disable the normal order action and offer enquiry if appropriate. Missing price is SQL NULL, not zero; reject negative prices.
- [ ] Centralize sample products and make placeholder fashion imagery unmistakably illustrative, never genuine client product photography. Provide image fallback and suitable loading behavior; optimize dimensions and lazy-load below-the-fold imagery. Demo content is easy to replace.

## Private admin authentication and dashboard
- [ ] Protect `/admin/login`, `/admin`, `/admin/products`, `/admin/products/new`, `/admin/products/:id/edit`, `/admin/categories` and `/admin/settings`. Use Supabase Auth email/password with official client session persistence/refresh, logout, protected routes, redirect to login when unauthenticated, and actionable auth/network errors. Do not ship public registration or passwords/secret credentials.
- [ ] Authenticated status alone does not confer admin rights. Verify the user ID in an explicitly provisioned `admin_users` allowlist and enforce every management action again through Supabase RLS/Storage policies; never rely only on a hardcoded frontend email comparison.
- [ ] Dashboard counts are calculated from real database records: total products, published products, drafts, unavailable products, categories and recently updated products. Provide Add product, Manage products, Manage categories, Open storefront and Update store settings actions. Do not fabricate sales, revenue, orders or conversion statistics. Show when WhatsApp/Supabase is not configured.
- [ ] Product manager provides thumbnail, name, category, price, publication state, availability, updated date, edit, publish/unpublish and confirmed delete; include search and filters, database error handling and safe image-reference behavior.

## Product/category/settings management
- [ ] Product form supports product name, unique valid slug, category, description, optional NGN price, main image and additional images, optional sizes/colours, fabric, care, availability, featured/new-arrival flags and draft/published status. Owner can upload multiple photos, preview them, choose a main photo, remove/replace photos, add/edit/remove sizes and colours, save draft, publish, edit, unpublish and mark unavailable. Products need not have sizes or colours; options are configured per product rather than hardcoded by category.
- [ ] Validate required fields with actionable messages; distinguish missing price from valid zero; reject negative price; convert NGN to integer kobo accurately; prevent duplicate/invalid slugs with graceful conflict handling; validate structured option arrays. Clean up replaced/deleted image objects safely where possible and avoid excessive orphans on failed writes.
- [ ] Categories management allows viewing, creation, editing of name/slug/optional description/image/public visibility/sort order, and prevents accidental deletion while products reference a category; provide safe reassignment or explicit confirmation.
- [ ] Store settings persist brand name, logo, WhatsApp number, Instagram URL, contact information, announcement text/visibility, About text, delivery information and other approved editable content. Validate URL and phone formats. If WhatsApp is absent, show a helpful configuration message and do not generate a misleading link. Only public-facing settings are stored publicly; never store secrets or private customer information there.

## Supabase schema, policies and data integration
- [ ] Version-control PostgreSQL SQL migrations for `admin_users`, `categories`, `products`, `product_images` and `store_settings`, using UUID keys where appropriate, foreign keys, timestamps and update behavior, indexes, constraints, safe delete behavior, status validation, nonnegative nullable integer-kobo price, structured options and deterministic initial settings/category strategy. Do not create unneeded application tables.
- [ ] Enable RLS on every application table. Public visitors can read published products only, visible categories, public store settings and images belonging to published products. Only an explicitly provisioned `admin_users.user_id` can manage products, categories, settings and image metadata. Anonymous users cannot insert/update/delete catalog/settings. Unpublished products are not exposed by public queries. Any security-definer helper sets a safe search path and restricts execution appropriately.
- [ ] Use a private product-image Supabase Storage bucket (or clearly justified equally safe arrangement). Restrict upload/update/delete to authorized admin IDs; allow reads only for published-product images and the authorized owner. Validate MIME types/extensions, maximum file size and count; use safe product-specific randomized keys. Store paths rather than hardcoded URLs and generate signed URLs; document setup and cleanup limitations.
- [ ] Shared data layer supports published product lists, categories, public settings, product slug lookup, admin product CRUD, categories/settings management and image upload/removal. Management requires a valid authorized session and remains protected by RLS/policies. Handle loading, empty/error/success states, form validation, expired sessions and network failures. Newly published changes appear without redeploy; no stale draft data is cached or exposed.

## WhatsApp ordering
- [ ] Reusable helpers validate a configured international phone number and construct a valid `https://wa.me/` URL using digits only, without spaces or leading plus, with URL-encoded message text.
- [ ] Product enquiry says “Hello, I am interested in ordering [Product Name].” and includes Product, selected Colour/Size only when applicable, Quantity, “Please confirm availability, final price, and delivery options.” and “Thank you.” Use current product data and only selections offered for that product. If price is missing, clearly state the customer must enquire for pricing.
- [ ] Custom-made enquiry says “Hello, I would like to enquire about a custom-made modest outfit.” and offers optional preferred style, colour and additional details, then asks how to discuss design, measurements, pricing and delivery, ending “Thank you.” Do not require measurements or sensitive personal details to begin.
- [ ] Open WhatsApp/WhatsApp Web only on a user-initiated action; give useful feedback if number is not configured; never claim order completion or payment receipt merely because WhatsApp opened. No payment gateway, checkout or automatic order confirmation.
